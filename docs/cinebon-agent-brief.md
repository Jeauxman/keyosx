# Brief: CinéBon editorial agent (first live agent for KeyOSX)

**Audience:** whoever builds and runs this service (Codex builds it; the writing engine is provider-independent, Claude suggested first).
**Goal:** one publication, CinéBon, runs the full loop for real: *observe -> request -> compose -> owner review -> approve -> archive.* Do not connect the other 14 publications until this one works reliably.
**Read first:** `docs/issue-agent-contract.md` (the wire format). This brief is the "what to build and how we'll judge it".

## 1. What CinéBon is

A **living weekly periodical for film lovers (cinephiles)**: film news, tips, ideas, and apps. Genre confirmed by Joe. A visitor sees the magazine cover on the KeyOSX kiosk, opens it, and gets a list of things to choose from (Jack Rabbit presents three starting picks, then the full list). Each issue is a *menu of opportunities for a film lover*, not a long article.

Cadence: **weekly** (period starts Monday UTC). Entity id: `keyosx:publication:cinebon`.

## 2. How the agent is called

1. A visitor opens a CinéBon cover in a new week. KeyOSX records the request (once per week) and `POST`s JSON to `ISSUE_GENERATOR_URL` with `Authorization: Bearer <AGENT_API_TOKEN>`:
   `{ publication_id, name, beat, cadence, period_key, issue_date, callback }`
2. **Answer 2xx immediately**, then work asynchronously (the visitor is shown "being composed").
3. When done, `POST {KeyOSX origin}/api/agent/issues` (same bearer token) with the issue.
4. **The post is always saved as a draft.** The owner approves it in the admin console. A silent or failed call is retried by KeyOSX with backoff (max 5 attempts), so make the webhook **idempotent per `period_key`**: if you already composed that period, don't compose twice; re-post only if you are deliberately submitting a revision.

Secrets: the token and origin come from environment variables on the agent's host. Never put them in code, logs, or the repo.

## 3. What an issue contains (CinéBon)

| Item | Count | Notes |
|---|---|---|
| `news` | 2-4 | **Only with a real, working source `url`.** See rule below. |
| `tip` | 2-3 | Practical: how to watch, host, learn, collect. |
| `idea` | 2-3 | Projects/clubs/events a film lover could start. |
| `app` | 2-3 | Real, existing tools/apps, with a `url`. Say what it is for. |
| `opportunity` | 1-2 | Things the reader can act on (festival, screening, community, partnership). |

- Total about **10-14 items**, titles short (under ~70 chars), `summary` 1-3 sentences.
- Mark **exactly 3** items `featured: true`: Jack Rabbit's opening picks. Make them different kinds (e.g. one news, one tip or idea, one app or opportunity) so the first choice has real options.
- `title` of the issue: e.g. `Week of 9 Nov 2026`. `issue_date` = today (UTC, `YYYY-MM-DD`) or later in the same week; it must be on/after the period start or KeyOSX will not treat the issue as current.

## 4. Non-negotiable content rules

1. **No invented facts.** A `news` item must be traceable to a source the agent actually retrieved this run (release dates, awards, casting, box office, festival lineups). If it cannot be sourced, it is *not* news: demote it to `idea`/`tip` or drop it.
2. Every `news` and `app` item carries an `http(s)` `url`. KeyOSX's review screen flags news with no link; the owner will reject those.
3. Prefer primary or reputable sources. Do not copy article text: write original one-to-three-sentence summaries and link out. Short titles only; no long quotations.
4. No claims about real people beyond what a cited source states. No gossip, no medical/legal/financial advice.
5. Do not use `is_sample`. That flag is only for the demo seed.
6. If research fails or finds too little, post a smaller, honest issue (or post nothing and let KeyOSX retry) rather than padding.

## 5. Cover

- A new cover each week, generated by the agent (Cloudinary image generation, or any generator) and **uploaded to Cloudinary** (cloud `dmsdspzbo`), folder suggestion `keyosx/covers/cinebon/`. Send the resulting HTTPS URL as `cover_url`. Suggested public id: `cinebon-<period_key>`.
- **Style reference** (existing CinéBon covers; the printed masthead must read **CinéBon**, matching these):
  - `ChatGPT_Image_Jun_23_2026_11_26_24_AM_tk8r7y` (v1782237405)
  - `ChatGPT_Image_Jun_23_2026_11_26_10_AM_bvn7kp` (v1782237406)
  - base URL: `https://res.cloudinary.com/dmsdspzbo/image/upload/<version>/<public_id>`
- Portrait (about 3:4), legible masthead, cover lines that echo that week's featured items. Check the cover text for typos before upload; image generators garble words.
- **Rights:** do not generate real people's likenesses or use studio posters/stills. Illustrative or stylized art only. If unsure, post the issue without a cover (the owner can reject or add one); never post a cover you could not verify.

## 6. Environment the agent needs

| Variable | Purpose |
|---|---|
| `AGENT_API_TOKEN` | Bearer token shared with KeyOSX (set the same value on both sides). |
| `KEYOSX_ORIGIN` | e.g. the branch preview origin, later `https://keyosx.com`. |
| model/search keys | Whatever the writing and research engines require. |

KeyOSX side: `ISSUE_GENERATOR_URL` = the agent's public webhook URL; it must be reachable from the Hostinger server (not `localhost`).

## 7. How to test before going live

1. Run KeyOSX locally (needs MySQL; see `README.md`) with `AGENT_API_TOKEN` and `ISSUE_GENERATOR_URL` set.
2. `scripts/mock-generator.mjs` is a stand-in agent: read it as the minimal reference implementation.
3. Open the CinéBon cover on a fresh week (or clear the `issue_requests` row) and watch: request -> your agent -> draft in the admin "Issues awaiting approval" panel -> approve -> visible on the cover.
4. Kill the agent mid-run and confirm KeyOSX retries (request goes `failed`, then retries after the backoff).

## 8. Acceptance criteria (CinéBon is "done" when)

- [ ] Opening the cover in a new week triggers exactly one composition run.
- [ ] A draft appears in the admin panel within a few minutes with 10-14 items, 3 featured, a real cover, and no unsourced news.
- [ ] Every `news` and `app` URL resolves.
- [ ] The owner can approve it and visitors see it; a second post for the same issue becomes revision 2 and does not change what visitors see until approved.
- [ ] Failure (agent down, source fetch fails, token wrong) leaves a clear error in the agent's logs and does not publish anything.
- [ ] Three consecutive weekly runs complete without manual intervention other than approval.

## 9. Out of scope (for now)

The other 14 publications; the fixed, printable 32-page edition; payments; Synphony orchestration. Build this one loop well first. When it is proven, the same service gets a per-publication config (beat, cadence, item mix, cover style) and nothing else changes.
